# Domain docs

This is a single-context repository.

Before engineering work, read the root `GLOSSARY.md` if present and the relevant ADRs in `docs/adr/`. The current project has ADRs under `docs/adr/`; a root glossary has not been established.

Do not create a glossary pre-emptively. Use `/domain-modeling` to settle terminology and create one only when there are stable terms worth recording. Keep implementation decisions in ADRs, not the glossary.
