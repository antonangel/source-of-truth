# Homelab sources of truth

Most homelab docs restate something a command can print. Generate that table instead of writing it,
or link to the config. If you must paste output, put a header above it (`generated by: <command>,
<date>`) so a stale copy is recognisable as one.

| Fact | Where the truth lives | Print it with |
|---|---|---|
| Services, ports, images | Compose files | `docker compose config`, `docker compose config --images` |
| What is actually running | The Docker daemon | `docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'` |
| Container networks and IPs | Docker | `docker network inspect <network>` |
| NixOS settings | The flake or `configuration.nix` | `nix eval .#nixosConfigurations.<host>.config.<option>` |
| Hosts and variables | Ansible inventory | `ansible-inventory --list` |
| Cloud or VM resources | Terraform / OpenTofu state | `terraform output`, `terraform state list` |
| VMs and containers on Proxmox | The hypervisor | `qm list`, `pct list` |
| Running units, timers | systemd | `systemctl list-units --type=service --state=running`, `systemctl list-timers` |
| Mounts and disks | The kernel | `findmnt`, `lsblk` |
| Local DNS records, proxy routes | The resolver's and proxy's own config files | link to the file |

## Rules of thumb

- A port, IP, image tag or path in prose is derived. Replace it with a link to the file that sets it.
- A list of services in `AGENTS.md` is derived. Point to the compose directory instead.
- What is **not** derivable is the reason: why this proxy, why that subnet, what was tried and
  dropped. That belongs in one ADR.
- Keep the generator next to the output. A table with no command that produces it is a decision
  wearing a table: relabel it as one, or delete it.
